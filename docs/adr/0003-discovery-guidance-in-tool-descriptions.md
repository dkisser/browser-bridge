# Discovery guidance lives in MCP tool descriptions

The eastmoney incident: an agent opened a news article and called `get_text` with the semantic guess `article`, but the page had no `<article>` tag (the body lives in `<div id="ContentBody">`), both lookup paths failed, and the agent burned a round-trip recovering. This is the same failure class as the Gmail incident behind ADR-0002: agents guess mandatory inputs (selectors here, row classes there) instead of discovering them. `TAB_ID_GUIDANCE` had already encoded one discovery step — "call tab_list first" — into tool descriptions; we decided that pattern is the canonical place for this guidance. Shared guidance fragments live in `apps/websocket/src/mcp/tool-descriptions.ts` and are appended to every tool whose primary input is a selector (`SELECTOR_GUIDANCE` on `get_text`, `get_html`, `click`, `type`, `select`, `hover`, `wait_element`; `snapshot`'s optional narrowing selector is exempt because snapshot is the discovery call itself), and the failure messages (`selectorNotFoundMessage`) repeat the same recovery steps for the post-failure moment. Because advice alone turned out to be ignorable, the not-found error also carries the observation itself — the extension appends the page's largest text containers — and the MCP `get_html` tool rejects payloads over 100K chars so whole-page dumps can't flood the caller's context. The working rule: model-facing copy is behavior — descriptions are the UI for LLM callers, and every input agents tend to guess gets a "discover first" sentence so the first call lands on discovery instead of the guess.

## Considered Options

- **Error-message-only fix**: change `selectorNotFoundMessage` and stop there. Cheapest, but the agent only learns after a failed call — on eastmoney-like pages the failure is guaranteed, not probabilistic. Rejected as the sole fix.
- **Auto-snapshot fallback on failure** (return candidate text containers when resolution fails): originally deferred as contract-changing, but a later transcript showed the limit of advice — an agent that had read the "take a full-page snapshot" error still guessed six selectors in a row (`.entry-content`, `.article-body`, `.post-content`, ...), then pivoted to whole-page `get_html` and drowned in 420K chars of chrome. Advice is ignorable under pressure; the observation has to arrive in-band. Implemented: `resolveSelector`'s not-found error now appends the page's largest text containers (extension-side, smallest-first so wrappers don't win), so the first failure already hands over the DOM observation.
- **Dedicated read/extract tool** (Readability-style, no selector): the right shape for scraping workflows, but the largest change (new command, handler, MCP tool, CLI surface). Deferred.
- **Skill-doc guidance only** (`SKILL.md`): kept as a complement — it now carries the navigate → wait:navigation → snapshot → gettext sequence — but it only reaches agents that load the skill, while MCP descriptions reach every caller. Not sufficient alone.
- **Description + error-message layer**: zero behavior change, effective for all MCP callers on the next session, wording is cheap to iterate. Chosen, consistent with the `TAB_ID_GUIDANCE` precedent.

## Consequences

- Guidance fragments belong in `tool-descriptions.ts` next to `TAB_ID_GUIDANCE`, each with a comment stating the intent (push the discovery call before the first guessed use). Keep them short — models re-read descriptions on every call.
- The same recovery advice now lives in three places: tool descriptions (pre-call), `selectorNotFoundMessage` (post-failure), and `SKILL.md` (skill-loaded agents). The duplication is deliberate — each reaches a different audience — but when editing one, check whether the other two need to move in step.
- Error-message wording is pinned by keyword assertions in `packages/shared/tests/messages.test.ts` (`CSS selector`, `visible text`, `snapshot`, `virtualized`, `@eN`, `tab_id`). Keep those keywords when rewording; extend the test for new guidance.
- `docs/mcp-setup.md`'s tool table is a summary and intentionally carries none of this wording; don't treat it as the place to document guidance.
- Text results over 100K chars (`MAX_READ_RESULT_CHARS` in `packages/shared/src/constants.ts`) are rejected at the MCP layer — `get_text` and `get_html` alike; the CLI path stays unrestricted. `snapshot` needed no guard (ADR-0002 budget + truncation stats) and `screenshot` returns image content, not context text. Escape hatches need guards, or "greedy compensation" becomes the path of least resistance after repeated failures.
- The candidate-container list in the not-found error is assembled extension-side; only its wording (`textContainerCandidatesHint`) lives in shared and is test-covered. If the heuristic misfires on real pages (wrapper winning, comment sections crowding out the article), tune the selection there — the contract is just the appended lines.
